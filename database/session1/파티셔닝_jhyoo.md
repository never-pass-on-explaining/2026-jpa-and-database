# 6장 파티셔닝

## 1. 파티셔닝이 필요한 이유

데이터 규모와 요청량이 증가하면 단일 노드의 저장 공간과 처리량만으로는 한계가 생긴다.
파티셔닝은 데이터셋을 여러 파티션으로 나누고 서로 다른 노드에 배치하는 방법이다.
- 저장 공간을 수평 확장한다.
- 읽기와 쓰기 부하를 여러 노드에 분산한다.
- 질의를 여러 노드에서 병렬로 처리한다.

파티셔닝의 핵심은 데이터의 분할 자체가 아니라 부하의 균등한 분산이다.
특정 파티션에 데이터나 요청이 몰리는 현상을 쏠림이라고 한다. 쏠림으로 부하가 집중된 파티션은 핫스팟이 된다.
따라서 파티셔닝 전략은 다음 질문에 답해야 한다.

- 데이터를 어떤 기준으로 나눌 것인가?
- 데이터와 요청을 얼마나 균등하게 분산할 수 있는가?
- 범위 질의와 특정 키 조회를 어떻게 처리할 것인가?
- 노드 구성이 바뀔 때 데이터를 얼마나 적게 이동할 것인가?

## 2. 파티셔닝과 복제

파티셔닝과 복제는 목적이 다르다.

- 파티셔닝: 데이터셋을 나눠 저장 공간과 처리량을 확장한다.
- 복제: 같은 데이터를 여러 노드에 저장해 가용성과 읽기 처리량을 높인다.

두 방식은 함께 사용할 수 있다. 각 파티션을 여러 노드에 복제하면 한 노드는 특정 파티션의 리더이면서 다른 파티션의 팔로워가 될 수 있다.

## 3. 키-값 데이터 파티셔닝

레코드의 키를 기준으로 저장할 파티션을 결정한다.
대표적인 방식은 키 범위 기준 파티셔닝과 해시 기준 파티셔닝이다.

### 3.1 키 범위 기준 파티셔닝

키를 정렬한 뒤 연속된 범위를 각 파티션에 할당한다. 파티션 경계는 데이터 분포에 따라 다르게 설정할 수 있다.
장점은 다음과 같다.

- 키의 정렬 순서를 유지한다.
- 연속된 키를 한 파티션에서 읽을 수 있다.
- 시간이나 구간을 기준으로 한 범위 질의에 유리하다.

단점은 다음과 같다.

- 특정 키 범위에 데이터가 몰리면 파티션 크기가 불균형해진다.
- 최신 시간처럼 요청이 집중되는 범위가 있으면 핫스팟이 발생한다.

시간순 키 앞에 장치나 사용자 식별자를 추가하면 쓰기를 분산할 수 있다. 대신 같은 시간대의 데이터를 조회할 때 여러 파티션의 결과를 모아야 한다.
즉, 쓰기 분산과 범위 조회 효율 사이에 트레이드오프가 있다.

### 3.2 해시 기준 파티셔닝

키의 해시값을 기준으로 파티션을 결정한다.
좋은 해시 함수는 가까운 키도 서로 다른 위치에 배치해 데이터를 비교적 균등하게 분산한다. 목적은 보안이 아니라 분산이다.
장점은 다음과 같다.

- 키 분포가 치우쳐 있어도 데이터를 균등하게 나누기 쉽다.
- 키 범위 기준 파티셔닝보다 구조적인 핫스팟을 줄이기 쉽다.

단점은 다음과 같다.

- 키의 정렬 순서를 잃는다.
- 범위 질의가 여러 파티션에 걸칠 수 있다.

즉, 해시 기준 파티셔닝은 분산에는 유리하지만 연속된 범위를 읽는 데는 불리하다.

### 3.3 복합 키 활용

복합 키를 사용하면 두 방식의 장점을 일부 결합할 수 있다.
첫 번째 컬럼의 해시값으로 파티션을 정하고, 나머지 컬럼으로 파티션 내부를 정렬한다.
예를 들어 사용자 식별자와 시간을 복합 키로 사용하면 사용자별 데이터는 한 파티션에 모으면서 시간 범위 질의를 지원할 수 있다.

### 3.4 핫 키 문제

해시 기준 파티셔닝도 특정 키 자체에 요청이 집중되는 문제는 해결하지 못한다. 같은 키는 항상 같은 파티션으로 이동하기 때문이다.
핫 키에 접두사나 접미사를 붙여 여러 키로 나누면 쓰기 요청을 분산할 수 있다.
그러나 읽을 때 분산된 키를 모두 조회하고 결과를 합쳐야 한다. 또한 어떤 키를 분산할지 애플리케이션이 관리해야 한다.
핫 키 분산은 쓰기 처리량을 얻는 대신 읽기 비용과 관리 복잡성을 높인다.

## 4. 파티셔닝과 보조 색인

기본키가 아닌 컬럼으로 조회하려면 보조 색인이 필요하다.
파티셔닝 환경의 보조 색인은 문서 기준 색인과 용어 기준 색인으로 나뉜다.

### 4.1 문서 기준 보조 색인

각 파티션이 자신에게 저장된 문서의 색인만 관리한다. 지역 색인이라고도 한다.
장점은 다음과 같다.

- 문서와 색인을 같은 파티션에서 갱신할 수 있다.
- 쓰기 과정이 단순하다.

단점은 다음과 같다.

- 원하는 값이 어느 파티션에 있는지 바로 알 수 없다.
- 조회 요청을 모든 파티션에 보내야 할 수 있다.
- 가장 느린 파티션이 전체 응답 시간을 결정할 수 있다.

여러 파티션에 요청을 보내고 결과를 합치는 방식을 스캐터/개더라고 한다.
문서 기준 색인은 쓰기 비용을 줄이는 대신 읽기 비용을 높인다.

### 4.2 용어 기준 보조 색인

보조 색인의 값을 기준으로 색인 자체를 파티셔닝한다. 전역 색인이라고도 한다.
장점은 다음과 같다.

- 검색할 값이 저장된 파티션만 조회할 수 있다.
- 문서 기준 색인보다 읽기가 효율적이다.

단점은 다음과 같다.

- 하나의 문서 변경이 여러 색인 파티션에 영향을 줄 수 있다.
- 분산 트랜잭션이나 비동기 갱신이 필요할 수 있다.
- 비동기 갱신 시 최신 변경이 즉시 검색되지 않을 수 있다.

용어 기준 색인은 읽기 비용을 줄이는 대신 쓰기 복잡성과 일관성 문제를 높인다.

### 4.3 선택 기준

보조 색인 방식은 읽기와 쓰기 중 무엇을 우선할지에 따라 선택한다.

- 쓰기가 많고 전체 파티션 조회를 감당할 수 있다면 문서 기준 색인이 적합하다.
- 특정 값 조회가 많고 복잡한 색인 갱신을 감당할 수 있다면 용어 기준 색인이 적합하다.

## 5. 파티션 리밸런싱

노드 추가, 데이터 증가, 장애가 발생하면 파티션을 노드 사이에서 다시 분배해야 한다. 이 과정을 리밸런싱이라고 한다.
좋은 리밸런싱은 다음 조건을 만족해야 한다.

- 노드 사이의 데이터와 요청 부하를 균등하게 만든다.
- 진행 중에도 읽기와 쓰기를 처리한다.
- 불필요한 데이터 이동을 최소화한다.

### 5.1 피해야 할 방식

노드 수를 기준으로 나머지 연산을 수행하면 노드 수가 바뀔 때 대부분의 키가 다른 노드로 이동한다.
노드 하나를 추가하거나 제거하는 작은 변화가 대규모 데이터 이동으로 이어지므로 리밸런싱에 적합하지 않다.

### 5.2 파티션 개수 고정

노드보다 많은 파티션을 미리 만들고 각 노드에 여러 파티션을 할당한다.
노드가 추가되면 파티션 경계는 유지한 채 일부 파티션의 노드 할당만 변경한다.
장점은 다음과 같다.

- 리밸런싱 과정이 단순하다.
- 이동할 데이터의 양을 조절하기 쉽다.

단점은 다음과 같다.

- 초기 파티션 수를 미리 정해야 한다.
- 파티션이 크면 이동과 복구 비용이 커진다.
- 파티션이 작으면 메타데이터와 관리 비용이 증가한다.

### 5.3 동적 파티셔닝

데이터 크기에 따라 파티션을 자동으로 분할하거나 병합한다. 키 범위 기준 파티셔닝에서 주로 사용한다.
장점은 데이터 규모에 맞춰 파티션 수가 조정된다는 점이다.
단점은 데이터가 적은 초기 단계에서 파티션 수가 부족해 요청이 한 노드에 몰릴 수 있다는 점이다. 이를 완화하려면 파티션을 미리 나누는 사전 분할을 사용할 수 있다.

### 5.4 노드 비례 파티셔닝

노드마다 일정한 수의 파티션을 유지한다.
노드가 추가되면 기존 파티션 일부를 분할해 새 노드에 할당한다. 노드 수가 늘어날수록 전체 파티션 수도 증가한다.

### 5.5 자동 리밸런싱과 수동 리밸런싱

자동 리밸런싱은 운영자의 개입을 줄이지만 일시적인 지연을 장애로 오인할 수 있다.
불필요한 데이터 이동은 네트워크와 디스크 부하를 높여 장애를 악화시킬 수 있다.
따라서 시스템이 이동 계획을 제안하고 운영자가 승인하는 절충 방식을 사용할 수 있다.

## 6. 요청 라우팅

클라이언트는 원하는 파티션이 어느 노드에 있는지 알아야 한다.
리밸런싱으로 파티션 위치가 바뀌므로 파티션과 노드의 매핑 정보를 지속해서 갱신해야 한다.
대표적인 라우팅 방식은 다음과 같다.

- 아무 노드에 요청하고 해당 노드가 올바른 노드로 전달한다.
- 별도의 라우팅 계층이 파티션 위치를 확인해 전달한다.
- 클라이언트가 파티션 정보를 관리하고 올바른 노드에 직접 요청한다.

매핑 정보는 ZooKeeper 같은 코디네이션 서비스로 관리할 수 있다. 또는 가십 프로토콜을 사용해 노드끼리 클러스터 상태를 공유할 수 있다.

## 7. 병렬 질의 실행

하나의 질의가 여러 파티션에 걸치면 각 노드가 일부 연산을 병렬로 수행한다.
각 노드의 부분 결과를 모아 최종 결과를 만든다.
이 방식은 대규모 분석 질의를 처리하는 MPP 데이터베이스에서 주로 사용한다.

## 8. 핵심 정리

파티셔닝 전략에는 모든 상황에 적합한 하나의 정답이 없다.

- 범위 질의가 중요하면 키 범위 기준 파티셔닝을 고려한다.
- 균등한 데이터 분산이 중요하면 해시 기준 파티셔닝을 고려한다.
- 쓰기 단순성이 중요하면 문서 기준 보조 색인을 고려한다.
- 특정 값의 조회 성능이 중요하면 용어 기준 보조 색인을 고려한다.
- 리밸런싱에서는 균등한 부하, 서비스 지속성, 최소한의 데이터 이동을 함께 고려한다.

결국 파티셔닝은 데이터 분포, 접근 패턴, 읽기와 쓰기의 비율, 운영 복잡성 사이의 트레이드오프를 선택하는 문제다.
